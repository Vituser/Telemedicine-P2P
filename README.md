# 🩺 Платформа телемедицинских консультаций (WebRTC + FastAPI + OpenCV)

Минималистичный прототип системы видеоконференцсвязи (ВКС) для телемедицины с гибридной архитектурой:
- **HTTP Signaling API**: управление комнатами, токенами и обмен WebRTC-сигналами (`Offer` / `Answer` / `ICE`) через HTTP-поллинг.
- **Direct P2P WebRTC**: прямая передача медиапотока (видео и звук) между браузерами врача и пациента в обход сервера (с использованием STUN-сервера Google).
- **Server-side Frame Analysis (OpenCV)**: фоновая передача JPEG-кадров от пациента на сервер (1 кадр/с), автоматическая детекция лица каскадом Хаара (`haarcascade_frontalface_default.xml`), отрисовка рамки и отправка результата врачу в реальном времени.

---

## 📋 Контракт HTTP API

Базовый префикс: `http(s)://<SERVER_HOST>:<PORT>`  
Все тела и ответы — JSON (за исключением отправки бинарного JPEG на `/frames` и HTML-страниц интерфейсов).

| Метод и путь | Кто вызывает | Описание | Код успеха | Авторизация |
| :--- | :--- | :--- | :---: | :--- |
| `GET /doctor` | Врач | Открывает веб-интерфейс кабинета врача | `200` | Не требуется |
| `GET /patient` | Пациент | Открывает веб-интерфейс кабинета пациента | `200` | Не требуется |
| `POST /rooms` | Врач | Создаёт комнату, выдаёт 6-значный `room` и токен врача | `201` | Не требуется |
| `POST /rooms/{room}/join` | Пациент | Занимает место пациента в комнате и получает токен | `200` | Не требуется |
| `POST /rooms/{room}/events` | Оба | Передаёт `offer`, `answer` или `ice` кандидаты | `202` | `Bearer <token>` |
| `GET /rooms/{room}/events?after=N` | Оба | Возвращает события для участника, начиная с индекса `N` | `200` | `Bearer <token>` |
| `POST /rooms/{room}/frames` | Пациент | Принимает JPEG-кадр, детектирует лица (OpenCV) и отправляет врачу | `200` | `Bearer <token>` |

## 🚀 Установка и запуск

### 1. Установка зависимостей
Убедитесь, что у вас установлен Python 3.9+, создайте виртуальное окружение и установите необходимые пакеты:

```bash
pip install -r requirements.txt
```

### 2. Настройка HTTPS (для работы камеры по локальной сети)
Браузеры блокируют доступ к камере и микрофону (`navigator.mediaDevices.getUserMedia`) на небезопасных соединениях (`http://`), если страница открыта не на `localhost` (например, при подключении пациента со смартфона по локальной Wi-Fi сети).

Если в корне проекта лежат файлы `cert.pem` и `key.pem`, сервер автоматически запустится по протоколу **HTTPS**. Сгенерировать их можно с помощью утилиты [mkcert](https://github.com/FiloSottile/mkcert):

```bash
mkcert -install
mkcert -cert-file cert.pem -key-file key.pem localhost 127.0.0.1 <ВАШ_ЛОКАЛЬНЫЙ_IP>
```
*(Если файлов `cert.pem` и `key.pem` нет в папке проекта, сервер запустится в обычном режиме по HTTP).*

### 3. Запуск сервера

```bash
python server.py
```

После запуска в консоли отобразятся готовые ссылки для подключения (порт по умолчанию — `8000`):
- **На ПК (Врач):** `https://localhost:8000/doctor`
- **На Телефоне / втором устройстве (Пациент):** `https://<ВАШ_ЛОКАЛЬНЫЙ_IP>:8000/patient`

## 💡 Сценарий использования
1. **Врач** открывает страницу `/doctor`, нажимает **«Создать комнату»** и разрешает доступ к камере и микрофону.
2. На экране врача появляется 6-значный **Код консультации** (например, `A1B2C3`), который передаётся пациенту.
3. **Пациент** открывает страницу `/patient`, вводит полученный код и нажимает **«Войти»**.
4. Между браузерами устанавливается прямое P2P-видеосоединение (WebRTC), а в правой панели у врача каждую секунду обновляется кадр с сервера OpenCV со статусом нахождения лица пациента в кадре.
